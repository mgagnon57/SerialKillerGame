# Names for Ashcombe. Rural, 1979 - adults born 1910-1960, children born 1965-1975.
# One directive per line: male | female | surname
#
# Forenames are drawn from the birth-registration commonplaces of those decades. Surnames lean
# West Country, because that is where Ashcombe is; a good few are deliberately unremarkable so
# that not every household sounds like a parish register, and a town of six hundred has always
# had incomers. Pethick, Halloran and Ivey must stay - village.txt names the shop, the surgery
# and the garage after them.
#
# -------------------------------------------------------------------------------------------
# SIZING. Read this before adding or cutting.
#
# Surnames are the load-bearing pool. PopulationGenerator draws one per household and, for
# Sharers, one per member, so a town of N people takes about  N/2.22 + 0.07N/2.22*2.5  draws:
#
#     109 people ->   57 draws over  74 surnames  =  0.77 households per surname
#     600 people ->  316 draws over  74 surnames  =  4.27   eighteen unrelated Hockings
#     600 people ->  316 draws over 401 surnames  =  0.79   where it stands now
#
# At 0.79 the generator's prefer-an-unused-surname loop still finds a fresh name for nearly
# every household, and the repeats that do land read as kin, which is what they should read as.
#
# Forenames are NOT sized the same way and must not be. Repetition is the realism here: 1979
# England ran on about fifty male and fifty female names, and a parish where no two men share a
# first name is the artificial thing. At 600 these pools give roughly two people per forename.
#
#     Real frequency was long-tailed - a dozen Johns and one Horace - and the generator draws
#     uniformly, so the tail is flat. If that ever wants fixing, the content-only lever is to
#     list a common name more than once (NameTable.Parse appends, so a repeat is a weight).
#     Nothing here is repeated today, deliberately, so that a duplicate is always a mistake.
#
# -------------------------------------------------------------------------------------------
# COHORTS. Forenames date. Drawn without regard to age, they produce a seven-year-old called
# Mavis and a nine-year-old called Douglas - the same class of fault as the pronoun bug, and
# currently shipping. The `male-child` and `female-child` directives at the foot of this file
# are the 1965-1975 cohort, and NameTable.Parse ignores any kind it does not recognise, so they
# are inert until it learns them. See the note in particulars.txt; it is the same fix.
