#  One row: <name>  <x,y x,y x,y ...>   the polyline it was derived from, in village metres.
#
#  WHY THIS FILE EXISTS. build-roads.py named alleys `alley1..alleyN` by DESCENDING LENGTH:
#
#      for i, a in enumerate(sorted(alleys, key=lambda a: -a["len"]), start=1)
#
#  So a name was never a name. It was a rank, and a rank is a property of the whole SET - add one
#  alley, lengthen one alley, change the derivation by a metre, and every alley after it in the
#  order silently becomes a different road. Anything that had referred to `alley12` was then
#  pointing at a different piece of ground with no error, no warning and nothing in a diff to
#  suggest it. `Content/animations.txt`-style hand references, the traffic weights, a note in the
#  browser map: all quietly wrong.
#
#  These 31 are the ranking as it stood on 2026-08-08. The generator matches each derived alley
#  against this file and keeps the name; anything genuinely new is numbered after the highest here.
#
#  MATCHED BY DISTANCE TO THE POLYLINE, NOT TO ITS MIDPOINT, and that distinction is the whole
#  correctness of the thing. Eleven of these are stitched runs whose joins land 39.5-92.5 m from
#  their own midpoint - so a midpoint-radius rule of any sane size orphans the very parent names
#  it was written to protect, and renames them anyway.
#
#  Nothing here is authored. It is a snapshot of a derivation, kept so the derivation can change
#  without renaming the town.
